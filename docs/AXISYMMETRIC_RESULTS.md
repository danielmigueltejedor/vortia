# Axisymmetric results and engineering reports

Generated Vortia axisymmetric cases can display a full 360° reconstruction of the saved fluid field around X. A case marker, a valid wedge angle in mesh-report.json and noSwirl=true in controlDict identify this context; arbitrary VTK/Fluent data is not automatically revolved. The original wedge remains available through Results → Display → Axisymmetric revolution. Mesh-only results can use revolution and sections even when no pressure or velocity has been exported.

The reconstruction interpolates the meridional Z=0 section, triangulates it, rotates coordinates and vector/tensor components, merges axis nodes and closes the angular seam. Tetrahedra, pyramids and wedges avoid degenerate axis cells. It is a visualization dataset, not a new CFD calculation or a solver-ready mesh. It assumes axisymmetry and cannot recover azimuthal instabilities. It is cached across field changes. The display uses 12–72 angular sectors with budgets of 750,000 cells, 1,500,000 points and an estimated 256 MiB for reconstruction data; oversized input retains the source wedge with an explicit notice. Original radial/axial sampling is retained.

Results → Sections offers longitudinal side (XY) and top (XZ) sections. Switching the camera between Side and Top also reorients an existing central longitudinal cut. Both keep axial X increasing from left to right; the XZ camera looks from negative Y with positive Z up. Show full domain restores the revolved envelope. Point probes, line profiles and plane sections use the displayed reconstructed field when revolution is active. Interpolated values are not additional CFD results. Exported PNGs identify the reconstruction or original wedge.

Results → Display → Velocity vectors overlays up to 1,200 sampled U arrows with automatic display scale. It is available only when U exists. Stored source arrays are not edited.

Results → Sample → Statistics and histogram reports the **original calculated fluid block**, even while the 360° reconstruction or a section is displayed. This avoids multiplying reported integrals by the visual repetition count. It reports cell-value extrema, a measure-weighted mean and population standard deviation, measured volume/area/length, field integral, valid/excluded counts and a weighted histogram. Original cell arrays take precedence. If only point data exists, values are averaged over each cell and the UI/CSV identifies this association. Signed imported cell volume is converted to positive geometric measure; zero/non-finite/ghost cells are excluded. CSV includes its original-block scope and cell/point association, summary values and histogram counts/measures/fractions. Coordinates use the application's CFD convention of metres.

Verification covers closed seams, positive reconstructed cell volumes, an axis and an annulus, rotated radial velocity in opposite angular positions, unmodified source arrays, volume-weighted analytical reports, signed imported ordering, field switching, generic versus recognized inputs, and mesh-only UI availability. Native Cocoa/OpenGL QA renders side/top/360° views and the statistics dialog from a private uniform-rest control using the user's saved geometry; its report volume is checked against OpenFOAM checkMesh. These images are UI QA from that rest control, not validation of the nozzle exercise. Existing native navigation/framebuffer regressions also run.

Useful implementation references: [VTK cell size filter](https://vtk.org/doc/nightly/html/classvtkCellSizeFilter.html), [VTK glyph mapper](https://vtk.org/doc/nightly/html/classvtkGlyph3DMapper.html).
